Sample defect report

Withdrawal is created twice when Submit is double-clicked

Severity
Critical
Priority
High
Environment
QA, Chrome on Windows
Role
Player
Steps
  1. Log in as a player with a balance of 100.
  2. Open Withdraw and enter 50.
  3. Double-click Submit quickly.
Expected
One withdrawal of 50 is created. The button locks after the first click.
Actual
Two withdrawal requests appear in history and the balance drops by 100.
Evidence
Screen recording and the duplicate API calls from the network tab.
Suggested fix
Disable the button on first click and make the endpoint reject duplicate requests.

Testing a payment flow

  1. Read the rules first: limits, fees, currencies and who is allowed to pay.
  2. Test the happy path with each payment method.
  3. Break it: declined cards, timeouts, double clicks, refreshing mid-payment, closing the tab.
  4. Check the numbers: amount, fee and balance must match on screen, in the API and in the database.
  5. Check every role sees only what it should.
  6. Automate the stable core, then re-run it after every release.

Sample automation

A Playwright check

A small example of the style I use: one clear behavior per test, readable names, and checks on what the user sees.

import { test, expect } from '@playwright/test';

test('agent cannot open the super admin area', async ({ page }) => {
  // log in as an agent
  await page.goto('/login');
  await page.getByLabel('Email').fill(process.env.AGENT_EMAIL);
  await page.getByLabel('Password').fill(process.env.AGENT_PASSWORD);
  await page.getByRole('button', { name: 'Log in' }).click();

  // try the restricted page directly
  await page.goto('/admin/users');
  await expect(page).not.toHaveURL(/admin\/users/);
  await expect(page.getByText('Access denied')).toBeVisible();
});

How I Work

Manual first to understand the product. Automation next to make quality repeatable.

I approach every product with a quality-first mindset. I start by understanding requirements, challenging assumptions, identifying risks, and exploring real-world user scenarios. I validate functionality across roles, workflows, business logic, calculations, APIs, and databases. Once a feature is stable, I build Playwright automation to make regression testing faster and more reliable. I also use Postman and JMeter to validate API behavior, data integrity, and application performance beyond what the UI reveals.
